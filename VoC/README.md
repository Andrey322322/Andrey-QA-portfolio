#  Практические кейсы по методологии VoC (Voice of the Customer)

В данном разделе представлены мои работы, выполненные на основе анализа реального пользовательского опыта « VoC голоса клиента». В рамках подхода «Черного ящика» я исследовал проблемы пользователей, трансформировал их в технические задачи для тестирования и сформулировал ожидаемые результаты для бизнеса.

---

###  Кейс 1: Нет отображения информации на карте
* **1. Жалоба/Проблема:** Пользователь открывает карту магазинов, но видит пустое серое поле. Не может понять, где забрать заказ.
* **2. Потребность:** Визуализация точек самовывоза для принятия решения о покупке.
* **3. Моё решение (QA):** Проверить доступность API карт; настроить вывод альтернативного текстового списка адресов при сбое API; проверить обработку ошибок при запрете геолокации в браузере.
* **4. Ожидаемый результат:** Пользователь гарантированно получает информацию о расположении точек, снижается процент брошенных корзин.
* 📄 **Оригинал документа:** [Открыть исходный PDF-кейс](./Кейс%20нет%20отображения%20информации%20на%20карте.pdf)

###  Кейс 2: Низкая скорость загрузки сайта интернет-магазина
* **1. Жалоба/Проблема:** Страницы товаров открываются слишком долго. Пользователи уходят с сайта, не дождавшись загрузки.
* **2. Потребность:** Быстрый отклик интерфейса для комфортного выбора товаров.
* **3. Моё решение (QA):** Провести аудит производительности (Performance Testing) через DevTools (Lighthouse); проверить размер и оптимизацию изображений; протестировать кэширование статических ресурсов.
* **4. Ожидаемый результат:** Время загрузки страницы снижается до целевых показателей, растет глубина просмотра сайта и конверсия.
* 📄 **Оригинал документа:** [Открыть исходный PDF-кейс](./Кейс%20низкая%20скорость%20сайта%20магазина.pdf)

###  Кейс 3: Сброс товаров из корзины при возврате на шаг назад
* **1. Жалоба/Проблема:** При попытке вернуться назад для редактирования заказа корзина полностью очищается. Приходится искать товары заново.
* **2. Потребность:** Сохранение состояния сессии и выбранных товаров при навигации по сайту.
* **3. Моё решение (QA):** Проверить работу LocalStorage/SessionStorage; протестировать поведение корзины при обновлении страницы (F5) и использовании кнопок «Назад/Вперед» в браузере.
* **4. Ожидаемый результат:** Пользователь не теряет собранный заказ при ошибках ввода, процесс оформления становится бесшовным.
* 📄 **Оригинал документа:** [Открыть исходный PDF-кейс](./Кейс%20сброс%20товаров%20из%20корзины%20при%20возврате%20на%20шаг%20назад.pdf)

###  Кейс 4: Сбой при оплате онлайн-заказа
* **1. Жалоба/Проблема:** После ввода данных карты появляется бесконечный лоадер или ошибка без объяснения причин. Деньги могут списаться, но статус заказа не меняется.
* **2. Потребность:** Безопасная, стабильная и прозрачная платежная транзакция.
* **3. Моё решение (QA):** Протестировать интеграцию с платежным шлюзом (API); проверить обработку негативных сценариев (недостаточно средств, неверный CVV, таймаут соединения); валидировать отправку вебхуков о смене статуса.
* **4. Ожидаемый результат:** Исключение ситуаций с «подвисшими» деньгами клиентов; понятные сообщения об ошибках на форме оплаты.
* 📄 **Оригинал документа:** [Открыть исходный PDF-кейс](./Кейс%20сбой%20при%20оплате%20онлайн%20заказа.pdf)

###  Кейс 5: Трудности с подбором мебели под интерьер комнаты
* **1. Жалоба/Проблема:** Сложно визуализировать, как диван или шкаф будут смотреться в реальной комнате. Покупатели боятся ошибиться с габаритами и цветом.
* **2. Потребность:** Инструмент для предварительной примерки товара в интерьере до совершения покупки.
* **3. Моё решение (QA):** Протестировать UX-логику конфигуратора/калькулятора размеров; проверить корректность масштабирования элементов 3D-моделей (или AR-модуля); валидировать передачу выбранных параметров (цвет, ткань) в итоговую корзину.
* **4. Ожидаемый результат:** Повышение вовлеченности пользователей; снижение процента возвратов из-за неподошедшего размера или цвета.
